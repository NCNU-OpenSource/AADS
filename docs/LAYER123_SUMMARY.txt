┃  LAYER 0: 數據收集                                                           ┃
┗━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━┛

    Docker Containers (stdout/stderr)
            │
            ↓
    Grafana Alloy ─────→ Loki (31天保留)
            │                  │

            │           TimescaleDB: raw_logs (永久保留)

    Prometheus ← cAdvisor/DCGM ← 系統 Metrics

┏━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━┓
┃  LAYER 1: 異常檢測 (每 10 秒輪詢)                                            ┃
┗━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━┛

    1. fetch_logs_from_loki()
       └→ query: {source="docker", container!="logbert"}
       └→ limit: 50 條/批
       
    2. LogBERTFilter.predict()
       ├─ 正規化日誌 (去時間戳/IP/UUID)
       ├─ Drain3 提取日誌模板
       ├─ BERT Masked Language Model 預測
       └─ anomaly_score > 0.5 → 標記為異常
       
       輸入:  50 條 RAW 日誌
       輸出:  15-25 條異常 (30-50%)
       
    3. AnomalyStore.store_batch()
       └→ INSERT INTO anomaly_logs (PostgreSQL)
          - 永久保留所有異常
          - 包含: template, anomaly_score, container

    效能: 125 logs/sec (GPU) | 14.3 logs/sec (CPU)

┏━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━┓
┃  LAYER 2: 根因分析 (每 30 秒輪詢)                                            ┃
┗━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━┛

│ Step 1: AnomalyConsumer.poll()                                          │
│         SELECT * FROM anomaly_logs WHERE id > last_id LIMIT 50          │

                              ↓
┌─────────────────────────────────────────────────────────────────────────┐

│                                                                          │

│                                                                          │
│   輸入: 50 條異常                                                        │
│   輸出: 4-7 個 Clusters                                                 │
│                                                                          │

│   cluster_3: layer2-analyzer (10 anomalies)                            │
│                                                                          │

┃  LAYER 3: 修復建議與通知                                                     ┃
┗━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━┛

┌─────────────────────────────────────────────────────────────────────────┐
│ _run_layer3(diagnosis)  ← 統一處理函數                                  │
└─────────────────────────────────────────────────────────────────────────┘

    Step 1: SuggestionGenerator.generate_suggestions()
            ├─ 根據 root_cause.category 匹配規則模板
            ├─ 合併 LLM 生成的 recommended_actions
            └─ 標記 safe_to_automate (唯讀操作)
            
            範例輸出:
            [
              {priority: 1, action: "check_network", 
               safe_to_automate: true, command: "ping -c 3 8.8.8.8"},
              {priority: 2, action: "check_firewall", 
               safe_to_automate: true},
              ...
            ]
            
    Step 2: format_for_notification()
            └─ 生成 Markdown 格式訊息
            
    Step 3: NotificationHub.send_notification()
            ├─ Severity Filter (檢查 >= medium)
            ├─ 並行發送:
            │  ├─ Slack (Webhook Blocks API)
            │  └─ Custom Webhook (JSON POST)
            └─ 返回 {slack: true, webhook: true}
            
    Step 4: store_diagnosis(diagnosis)
            └─ INSERT INTO diagnosis_reports (TimescaleDB)
               - 永久保留所有診斷
