# 專題作品：AADS — AI 自動除錯系統

> **AI Auto Debug System**：結合大型語言模型（LLM）與自動化維運的伺服器故障「偵測 → 診斷 → 修復」閉環系統
> 原始碼：github.com/bs10081/AADS ｜ 開放原始碼（MIT License）

---

## 一、專案簡介

伺服器服務（如 Nginx、PostgreSQL、Redis、MySQL）故障時，工程師需要翻閱大量日誌、判斷原因、再手動修復，耗時且依賴經驗。AADS 嘗試把這個流程自動化：系統持續收集主機日誌，從中過濾出異常，交給 LLM 進行根因分析並產生修復計畫；計畫經過**人工審批**後，由執行器在目標主機上自動完成修復，全程留下可追溯的稽核紀錄。

這個專案最大的挑戰不是「讓 AI 修東西」，而是「**如何讓 AI 修東西時絕對安全**」：LLM 可能產生錯誤指令（幻覺），也可能被日誌中的惡意內容誘導（提示注入）。因此整個系統的核心設計是——LLM 只負責「推理與建議」，所有實際執行都被關在確定性、可驗證、可回復的安全邊界內。

## 二、系統架構與運作流程

```
日誌收集 ──▶ 異常過濾 ──▶ LLM 根因分析 ──▶ 人工審批閘道 ──▶ 自動執行修復
(Alloy/Loki)  (Drain3/      (LangGraph +      (Web Dashboard)   (確定性執行器 +
               LogBERT)      修復計畫產生)                        快照回滾機制)
```

1. 目標主機的日誌即時轉送到集中式日誌系統，異常過濾層從海量日誌中挑出異常事件。
2. LLM 代理（Agent）查詢日誌與系統指標，分析根本原因，產生結構化的修復計畫。
3. 管理者在 Dashboard 上檢視計畫內容，手動核准後才允許執行。
4. 執行器先建立設定檔快照（確保可回滾），再逐步執行修復，每一步都有自動驗證。

實際成果：系統已能在實驗環境中，**全自動偵測並修復 Nginx 設定檔錯誤、PostgreSQL 停機、Redis 與 MySQL 設定錯誤**等故障情境，並通過混沌測試（Chaos Testing）驗證在斷線、衝突、程序崩潰等邊界情況下的安全性。

## 三、使用技術

| 領域 | 技術 |
|------|------|
| 後端開發 | Python（FastAPI、Flask）、RESTful API、Pydantic 資料驗證 |
| AI / LLM | LangChain、LangGraph（Agent 工作流）、LiteLLM、提示工程與防注入設計 |
| 機器學習 | LogBERT（Transformer 日誌異常偵測，PyTorch） |

| 可觀測性 | Grafana、Prometheus、Loki 日誌系統 |
| 軟體工程實務 | Git 版本控制、pytest 單元測試、端對端（E2E）自動化測試、技術文件與 ADR 撰寫 |

## 四、我在專案中的學習與成長

- **資訊安全思維**：設計了「LLM 不能直接產生指令」的防注入架構——LLM 輸出只能是語意化的操作名稱，由確定性程式翻譯成固定指令，並以最小權限原則控管主機上的特權操作。
- **分散式系統實務**：處理了並行鎖（node lock）、冪等性（idempotency）、程序崩潰後的狀態恢復等真實世界的可靠性問題。
- **從失敗中修正設計**：在實際展示中發現 MySQL 設定檔判斷錯誤、高流量下日誌漏讀等問題，學會透過測試重現問題、分析根因、再回頭修正架構。
- **完整的工程流程**：從需求分析、架構設計、實作、測試到文件撰寫，完整走過一個軟體系統的開發週期。

這個專案讓我深刻體會到：寫出能動的程式只是起點，**讓系統在各種邊界情況下仍然安全、可控、可回復**，才是電腦科學與軟體工程真正的深度。這也是我希望在資訊工程領域繼續深造、補強理論基礎（作業系統、資料庫、機器學習）的主要動機。
